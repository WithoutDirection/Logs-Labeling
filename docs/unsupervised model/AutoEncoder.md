# AutoEncoder

## 概述

**AutoEncoder（自編碼器）** 是一種基於深度神經網路的非監督式異常偵測方法。其核心理念是：**讓網路學習將輸入資料壓縮成低維表示後再重建，正常資料可被良好重建，而異常資料的重建誤差較大**。

在日誌異常偵測中，AutoEncoder 能夠學習正常日誌模式的「本質特徵」，對於偏離這些模式的異常行為產生顯著的重建誤差。

---

## 核心機制

### 編碼-解碼架構

AutoEncoder 由兩個主要部分組成：

```
Input (768-dim) → Encoder → Latent (32-dim) → Decoder → Output (768-dim)
    原始嵌入      壓縮過程     壓縮表示      還原過程     重建嵌入
```

- **Encoder（編碼器）**：將高維輸入壓縮至低維潛在空間
- **Latent Space（潛在空間）**：資料的壓縮表示，保留關鍵資訊
- **Decoder（解碼器）**：從潛在空間重建原始輸入

### 重建誤差作為異常分數

訓練目標是最小化重建誤差（Mean Squared Error）：

$$
\text{MSE} = \frac{1}{d} \sum_{i=1}^{d} (x_i - \hat{x}_i)^2
$$

異常偵測邏輯：
- **正常資料**：符合訓練時學到的模式，重建誤差低
- **異常資料**：偏離學習模式，重建誤差高

### 資訊瓶頸原理

潛在空間維度遠小於輸入維度，形成「資訊瓶頸」：
- 強迫網路學習**最重要的特徵**
- 去除冗餘與噪聲
- 異常模式難以通過瓶頸

## 演算法特性

### 優勢

| 特性 | 說明 |
|------|------|
| **非線性特徵學習** | 深度網路能捕捉複雜的非線性模式 |
| **自適應特徵** | 自動學習資料的最重要特徵，無需手動特徵工程 |
| **語義壓縮** | 潛在空間保留語義資訊，對嵌入向量特別有效 |
| **可擴展性** | 支援 GPU 加速，處理大規模資料 |
| **遷移能力** | 在相似領域資料間可遷移學習 |

### 限制

| 限制 | 說明 |
|------|------|
| **過擬合風險** | 訓練輪數過多可能學會重建異常 |
| **訓練時間** | 相比統計方法需要更多計算資源 |
| **超參數敏感** | 結構與訓練參數需要調整 |
| **小樣本限制** | 資料量過小時難以有效學習 |

## 在本專案的應用

### 適用場景

AutoEncoder 在本專案中扮演**語義模式學習器**的角色：

1. **正常行為建模**：學習正常日誌的嵌入向量分佈模式
2. **語義異常偵測**：識別語義上偏離正常的攻擊行為
3. **壓縮表示提取**：潛在空間可作為下游任務的特徵

### 與 BERT 嵌入的契合度

| 嵌入特性 | AutoEncoder 優勢 |
|----------|------------------|
| 高維度（768 維） | 有效壓縮至 32 維，保留關鍵語義 |
| 語義連續性 | 非線性映射捕捉語義空間結構 |
| 噪聲存在 | 資訊瓶頸具有去噪效果 |

### 互補性貢獻

在 Ensemble 策略中，AutoEncoder 提供獨特的學習視角：

| 與其他模型比較 | AutoEncoder 獨特性 |
|----------------|-------------------|
| vs. Isolation Forest | IF 基於距離，AE 基於學習的重建能力 |
| vs. COPOD | COPOD 基於統計，AE 基於神經網路學習 |
| vs. PCA+GMM | PCA 是線性壓縮，AE 是非線性壓縮 |

### 日誌異常類型適用性

| 攻擊類型 | AutoEncoder 偵測效果 | 原因 |
|----------|---------------------|------|
| **語義偏離攻擊** | ★★★★★ | 攻擊語義難以被正常模式重建 |
| **複雜多步驟攻擊** | ★★★★☆ | 學習序列語義模式 |
| **微小變異攻擊** | ★★★☆☆ | 變異過小可能被成功重建 |
| **全新攻擊類型** | ★★★★☆ | 未知模式的重建誤差通常較高 |

## 網路架構設計

### 本專案採用的架構

```
Encoder:
  [768] → Linear → ReLU → BatchNorm → [128]
  [128] → Linear → ReLU → BatchNorm → [64]
  [64]  → Linear → [32] (Latent)

Decoder:
  [32]  → Linear → ReLU → BatchNorm → [64]
  [64]  → Linear → ReLU → BatchNorm → [128]
  [128] → Linear → [768] (Reconstructed)
```

### 設計考量

| 設計選擇 | 原因 |
|----------|------|
| **逐層壓縮** | 漸進壓縮避免資訊損失過劇 |
| **BatchNorm** | 穩定訓練，加速收斂 |
| **ReLU 激活** | 引入非線性，避免梯度消失 |
| **對稱結構** | 編碼與解碼能力對等 |

## 異常偵測原理深入

### 為何異常難以重建？

1. **訓練資料偏向正常**
   - 大多數日誌為正常行為
   - 網路學習的是正常模式的重建能力

2. **資訊瓶頸過濾**
   - 潛在空間有限（32 維）
   - 只能編碼「常見」的特徵組合
   - 異常的特徵組合無法有效編碼

3. **梯度優化方向**
   - 損失函數優化降低正常樣本的重建誤差
   - 間接提高異常樣本的重建誤差

### 重建誤差分佈

理想情況下：
- **正常樣本**：重建誤差集中在低值區域
- **異常樣本**：重建誤差散布在高值區域
- **閾值決策**：在兩者之間設定閾值

## 參數調整指南

### 關鍵參數

| 參數 | 建議值 | 影響 |
|------|--------|------|
| **latent_dim** | 16-64 | 太小損失資訊，太大失去瓶頸效果 |
| **hidden_dims** | [128, 64] | 層數與寬度影響表達能力 |
| **epochs** | 30-100 | 過多可能過擬合 |
| **batch_size** | 32-128 | 影響梯度穩定性 |
| **learning_rate** | 1e-3 到 1e-4 | 過高震盪，過低收斂慢 |

### 調整策略

- **誤報過多** → 減少訓練輪數、增加潛在維度
- **漏報過多** → 增加訓練輪數、減少潛在維度
- **訓練不穩定** → 降低學習率、增加 BatchNorm
- **過擬合** → 增加 Dropout、提早停止訓練
